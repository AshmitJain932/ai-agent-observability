# Canonical Event Model — v1 (draft)

Status: **Phase 0 draft**. Becomes normative as `schema/v1/ingest.schema.json` in Phase 1; until
then, this document is the design reference and may change.

## 1. Concepts and hierarchy

```
organization
└─ project                         (tenant boundary; owns API keys, policies, retention)
   └─ environment                  (free-form name: dev, staging, production, …)
      └─ session  (optional)       (a conversation / ticket / job grouping several runs)
         └─ run  ≡  trace          (one end-to-end agent execution)
            └─ span (tree)         (agent, llm, tool, retrieval, embedding, step, custom …)
               └─ span event       (point-in-time: retry, handoff, stream milestone, custom)
```

- **A run is a trace.** The run's root span has `kind: "agent"`. Keeping a 1:1 mapping keeps
  queries simple and maps directly to OpenTelemetry. Work that genuinely belongs to a different
  execution (a background job kicked off by a run) gets its own trace and a **link** back.
- **Multi-agent:** a sub-agent invoked in-process is a child `agent` span inside the same trace.
  A handoff is recorded as a `handoff` span event on the delegating span *and* a link on the
  receiving agent span, so it is visible whichever side you start from.
- **Session** is just an indexed `session_id` string on spans; there is no session table in v1.

## 2. Identifiers

| ID | Format | Generated by | Notes |
|---|---|---|---|
| `trace_id` | 32 lowercase hex chars (16 bytes), not all zero | SDK | W3C Trace Context / OTel compatible, so OTLP data maps losslessly |
| `span_id` | 16 lowercase hex chars (8 bytes), not all zero | SDK | Unique within a trace |
| `event_id` | UUIDv7 string | SDK | Only for span events; time-ordered, idempotency key |
| `batch_id` | UUIDv7 string | SDK | Optional, diagnostics only |
| `project_id` | server UUID | Server | **Never accepted from the client**; derived from the API key |

Idempotency key for spans is the natural key `(project_id, trace_id, span_id)` plus the event
type, so retried batches are harmless.

## 3. Wire envelope

`POST /v1/ingest` — `Content-Type: application/json`, optional `Content-Encoding: gzip`.

```json
{
  "schema_version": "1.0",
  "batch_id": "0192f4a1-7c3e-7b10-9a2d-5f6e1c0b8d41",
  "sent_at": "2026-10-12T12:15:03.120000Z",
  "resource": {
    "service_name": "support-agent",
    "service_version": "git:3f9c2e1",
    "environment": "production",
    "sdk": { "name": "aobs-python", "version": "0.1.0", "language": "python", "runtime": "cpython-3.12.4" },
    "integrations": [
      { "name": "openai_compat", "version": "0.1.0",
        "capabilities": ["llm.usage", "llm.streaming", "llm.request_params", "tool.calls"] }
    ],
    "capture": { "mode": "metadata_only", "capture_stack": false }
  },
  "events": [ /* span_start | span_end | span_event, in any order */ ]
}
```

`resource` describes *who sent this*; it is deduplicated server-side and referenced from each span.
`capture` declares the SDK's privacy settings so the UI can say "not captured (policy)" instead of
"missing".

## 4. Event types

| `type` | Required fields | Meaning |
|---|---|---|
| `span_start` | `trace_id`, `span_id`, `kind`, `name`, `start_time` (+ `parent_span_id` if not root) | A span began. Optional but recommended: it is what lets crashed or still-running work be visible. |
| `span_end` | Everything in `span_start` **plus** `end_time`, `duration_ms`, `status` | Final, self-contained record. Can arrive without a start. |
| `span_event` | `event_id`, `trace_id`, `span_id`, `name`, `time` | Point-in-time annotation on a span. |

## 5. Span fields

Common fields (all kinds):

| Field | Type | Notes |
|---|---|---|
| `trace_id`, `span_id` | hex strings | §2 |
| `parent_span_id` | hex or `null` | `null` means root. Never inferred by the server. |
| `links` | array of `{trace_id, span_id, relation}` | `relation`: `follows_from`, `triggered_by`, `handoff_from`, `retry_of` |
| `kind` | string | Known: `agent`, `llm`, `tool`, `retrieval`, `embedding`, `step`, `custom`. Reserved for later: `guardrail`, `evaluation`. Pattern `^[a-z][a-z0-9_.]{0,63}$`; unknown kinds accepted and rendered generically. |
| `name` | string ≤ 256 | Human label, e.g. `answer_ticket`, `chat`, `get_order_status` |
| `start_time`, `end_time` | RFC 3339 UTC, µs precision | Wall clock, for placement on a timeline |
| `duration_ms` | number ≥ 0 | **Measured with a monotonic clock** by the SDK; authoritative over `end_time − start_time` |
| `status` | `ok` \| `error` \| `cancelled` | Only on `span_end`. Absence = not finished. |
| `error` | object | `{type, message, code?, origin, retryable?, stack?}`; `origin`: `application`, `provider`, `tool`, `timeout`, `instrumentation`, `unknown` |
| `session_id` | string ≤ 256 | Optional grouping |
| `end_user_id` | string ≤ 256 | Optional, pseudonymous; SDK can hash it |
| `agent` | `{name, id?, version?}` | Set on `agent` spans; inherited for filtering |
| `prompt` | `{name?, version?}` | Prompt template identity (no content) |
| `retry` | `{attempt, max_attempts?}` | Each attempt is its own span; `retry_of` link points to the previous attempt |
| `attributes` | map string → scalar \| array of scalars | Namespaced keys (`openai.system_fingerprint`, `app.customer_tier`). Limits: 128 keys, key ≤ 128 chars, value ≤ 4 KiB. Reserved prefixes: `aobs.`, `gen_ai.` |
| `content` | object | §7. Subject to capture policy; stored separately. |

Kind-specific blocks (present only when relevant; every field optional unless noted):

**`llm`**
```json
"llm": {
  "provider": "openai",                    // required for kind=llm; free-form, lowercase
  "operation": "chat",                     // chat | completion | embeddings | responses | other
  "request_model": "model-x",
  "response_model": "model-x-2026-08-01",
  "request": { "temperature": 0.2, "max_tokens": 512, "stream": true, "tool_count": 3 },
  "response": { "id": "resp_…", "finish_reasons": ["tool_calls"] },
  "provider_request_id": "req_…",
  "streaming": { "time_to_first_token_ms": 312.4, "chunk_count": 41, "completed": true }
}
```

**`tool`**
```json
"tool": {
  "name": "get_order_status",              // required for kind=tool
  "type": "function",                      // function | mcp | http | browser | db | file | other
  "call_id": "call_abc123",                // id assigned by the model, links back to the llm span
  "arguments_fingerprint": "sha256:9f2c…", // always computed, even in metadata_only mode
  "mcp": { "server": "orders-mcp", "method": "tools/call" }
}
```

**`usage`** (on `llm` and `embedding` spans)
```json
"usage": {
  "input_tokens": 812, "output_tokens": 95,
  "cache_read_input_tokens": 512, "cache_write_input_tokens": null,
  "reasoning_tokens": null,
  "source": "provider_reported"            // provider_reported | sdk_estimated
}
```

**`cost`** (client-supplied only when the provider itself reports cost)
```json
"cost": { "amount": "0.000731", "currency": "USD", "source": "provider_reported" }
```

## 6. Unknown, estimated, measured — value semantics

This is the rule that keeps the product honest:

| State | Representation | Example |
|---|---|---|
| **Measured / reported** | Field present with a value, and a `source` where provenance matters | `input_tokens: 812, source: provider_reported` |
| **Estimated** | Field present, `source` says estimate | `source: sdk_estimated` (e.g. tokenizer count for a provider without usage) |
| **Unknown / not reported** | Field **absent** or `null` | No `usage` block on a streaming call whose provider omits usage |
| **Not captured by policy** | `content.*.status = "not_captured"` | metadata-only mode |
| **Redacted** | `content.*.status = "redacted"` + count of redactions | |
| **Unavailable from integration** | Capability not declared in `resource.integrations[].capabilities` | UI: "this integration cannot report usage" |

Rules:

1. **Absent never means zero.** Aggregates report a value *and* completeness, e.g.
   `input_tokens_sum: 4210, input_tokens_complete: false (2 of 7 LLM spans missing usage)`.
2. **Costs are never computed from unknown inputs.** If tokens or the model price are missing, the
   span's estimate is `null` with a reason (`missing_usage`, `unpriced_model`).
3. **Server-derived values are stored separately from client values** — the platform estimate
   lives in `cost_estimate {amount, currency, pricing_version, basis}`, next to (not replacing) any
   provider-reported `cost`.
4. Money is a decimal **string**, never a float.

## 7. Content (prompts, responses, arguments, results)

```json
"content": {
  "input":  { "status": "captured", "format": "messages", "value": [ … ], "truncated": false },
  "output": { "status": "redacted", "format": "text", "value": "My email is [REDACTED:email]", "redactions": 1 }
}
```

`status`: `captured` | `redacted` | `truncated` | `not_captured` | `unavailable`.
`format`: `text` | `messages` | `json`. Message shape aligns with the OpenTelemetry GenAI
`{role, parts[]}` structure so it converts directly. The server strips `value` when the project's
policy is stricter than the SDK's and records `not_captured`.

## 8. Span events

```json
{ "type": "span_event", "event_id": "0192f4a1-…", "trace_id": "…", "span_id": "…",
  "name": "handoff", "time": "2026-10-12T12:15:02.410000Z",
  "attributes": { "aobs.handoff.from_agent": "triage", "aobs.handoff.to_agent": "refund_specialist" } }
```

Well-known names: `handoff`, `retry.scheduled`, `stream.first_chunk`, `log`, `exception` (for
handled exceptions that did not fail the span). Anything else is custom.

## 9. Ordering, completeness and merge rules

| Rule | Detail |
|---|---|
| Order independence | Events may arrive in any order across batches; the stored result must be identical for any permutation (tested with property-based tests). |
| Merge | `span_end` fields win over `span_start`; `attributes` are unioned (end wins on conflict); `status` set once. |
| Duplicates | Identical re-submissions are no-ops; conflicting `span_end`s keep the first and increment a diagnostic counter. |
| Lifecycle (derived, query-time) | `complete` (has end) · `in_progress` (start only, younger than stale threshold) · `incomplete` (start only, older) · `orphaned` (parent id references a span not present) |
| Trace status (derived) | `incomplete` if no root span has ended (or no root arrived) · `error` if the root ended `error` · `cancelled` if the root ended `cancelled` · `ok_with_errors` if the root ended `ok` but some descendant errored (e.g. a retried call) · `ok` otherwise |
| Clock skew | Never rewritten. If a child is outside its parent's window by > 50 ms (configurable), flagged `clock_skew_suspected`. |

## 10. Versioning and evolution

- Envelope carries `schema_version: "MAJOR.MINOR"`.
- **Minor** versions only add optional fields, kinds, enum values or event names. Servers accept
  any minor of a supported major; unknown fields are preserved in `extra` and counted, not rejected.
- **Major** versions may remove or change meaning. The server supports the current and previous
  major for at least 12 months; old payloads are upgraded in the normalization step.
- `schema/CHANGELOG.md` records every change; a CI test fails if `ingest.schema.json` changes
  without a version bump.
- Fixtures under `schema/fixtures/` are the conformance suite for every SDK and for the server.

## 11. Mapping to OpenTelemetry GenAI (for Phase 7)

The OTel GenAI conventions now live in `open-telemetry/semantic-conventions-genai` and are
marked *Development*. We map at the boundary rather than adopting their names internally:

| Canonical | OTel attribute |
|---|---|
| `llm.provider` | `gen_ai.provider.name` |
| `llm.operation` | `gen_ai.operation.name` (`chat`, `embeddings`, `execute_tool`, `invoke_agent`, …) |
| `llm.request_model` / `response_model` | `gen_ai.request.model` / `gen_ai.response.model` |
| `usage.input_tokens` / `output_tokens` | `gen_ai.usage.input_tokens` / `gen_ai.usage.output_tokens` |
| `usage.cache_read_input_tokens` | `gen_ai.usage.cache_read.input_tokens` |
| `tool.name` / `tool.call_id` | `gen_ai.tool.name` / `gen_ai.tool.call.id` |
| `agent.name` / `agent.id` / `agent.version` | `gen_ai.agent.name` / `.id` / `.version` |
| `session_id` | `gen_ai.conversation.id` |
| `content.input` / `content.output` | `gen_ai.input.messages` / `gen_ai.output.messages` (opt-in in OTel too) |

## 12. Example: one run, with relationships

A support agent answers a ticket, calls a tool, hands off to a refund agent whose tool times out.

```
trace 4bf92f3577b34da6a3ce929d0e0e4736   run "answer_ticket"     agent   2.84 s  ERROR
├─ a1 llm   chat  model-x  attempt 1      0.91 s  ok      812 in / 95 out tokens
├─ a2 tool  get_order_status              0.12 s  ok      args sha256:9f2c…
├─ a3 llm   chat  model-x                 1.20 s  ok      usage: not reported (stream)
│   · event stream.first_chunk  +312 ms
├─ a4 agent refund_specialist             0.55 s  ERROR   link handoff_from → root
│   └─ a5 tool issue_refund               0.50 s  ERROR   TimeoutError (origin: timeout)
└─ · event handoff  triage → refund_specialist
```

What the platform can then say, honestly:

- 2 LLM calls, 2 tool calls, 1 sub-agent; failure located at `a5 issue_refund` (timeout).
- Input tokens ≥ 812 — **partial** (1 of 2 LLM calls reported usage).
- Estimated cost: partial, priced on 1 of 2 calls, pricing table `2026-10`.
- Prompt and argument content: not captured (metadata-only mode).

The matching JSON for spans `root`, `a2` and `a5`:

```json
[
  { "type": "span_start", "trace_id": "4bf92f3577b34da6a3ce929d0e0e4736", "span_id": "00f067aa0ba902b7",
    "parent_span_id": null, "kind": "agent", "name": "answer_ticket",
    "start_time": "2026-10-12T12:15:00.000000Z", "session_id": "ticket-8812",
    "agent": { "name": "triage", "version": "1.4.0" } },

  { "type": "span_end", "trace_id": "4bf92f3577b34da6a3ce929d0e0e4736", "span_id": "b7ad6b7169203331",
    "parent_span_id": "00f067aa0ba902b7", "kind": "tool", "name": "get_order_status",
    "start_time": "2026-10-12T12:15:00.930000Z", "end_time": "2026-10-12T12:15:01.050000Z",
    "duration_ms": 120.4, "status": "ok",
    "tool": { "name": "get_order_status", "type": "function", "call_id": "call_abc123",
              "arguments_fingerprint": "sha256:9f2c4e…" },
    "content": { "input": { "status": "not_captured" }, "output": { "status": "not_captured" } } },

  { "type": "span_end", "trace_id": "4bf92f3577b34da6a3ce929d0e0e4736", "span_id": "e457b5a2e4d86bd1",
    "parent_span_id": "5fb397be34d26b51", "kind": "tool", "name": "issue_refund",
    "start_time": "2026-10-12T12:15:02.300000Z", "end_time": "2026-10-12T12:15:02.800000Z",
    "duration_ms": 500.2, "status": "error",
    "tool": { "name": "issue_refund", "type": "http" },
    "error": { "type": "TimeoutError", "message": "refund API did not respond within 500 ms",
               "origin": "timeout", "retryable": true } }
]
```

Note the root above has only a `span_start` in this excerpt; if its `span_end` never arrives, the
run shows as **incomplete**, not successful.
